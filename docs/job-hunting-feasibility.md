# Job Hunting v0.1 可行性与支持边界

## v0.1 支持内容

v0.1 的工作流采用本地优先方式：

- 岗位来自用户选择的本地 JSON 或 Markdown 文件。导入器保留来源 URL、时间戳和来源标签，
  再执行标准化和去重。
- 简历支持 DOCX、文字型 PDF、TXT 和 Markdown。DOCX 使用 `mammoth` 读取，PDF 只提取
  已有文字层。
- 扫描版 PDF 会明确拒绝；加密 PDF、图片和其他不支持的格式也会拒绝。v0.1 不进行 OCR、
  解密，也不会上传文件处理。
- 匹配和报告使用已确认的求职画像，并保留证据边界；不会虚构经历或岗位历史。

## 静态网站与 `file://`

生成的 JH / 求职情报站 / Job Hunting 网站会在构建阶段内嵌岗位数据，不依赖运行时
`fetch()` 相邻 JSON 文件，因此生成的 `index.html` 可以通过 `file://` 打开。浏览器
`localStorage` 只作为当前浏览器中的临时兴趣标记存储。

## 可选的 DSH 原生 Schedule

可以通过独立的宿主层 overlay 在当前 DSH 会话中创建 Schedule 提醒，但这不改变本地优先和
人工确认边界。Schedule 只负责到时间提醒；提醒到期后，用户仍需确认具体白名单 URL 和只读
采集范围，插件才会调用 BrowserSkill 采集并生成报告。Schedule 不保证 Windows 后台 Cron、
无人值守爬虫或新会话自动继承提醒。

## v0.1 不承诺的能力

本版本不承诺 OCR、任意网站爬取、可靠的无人值守后台任务、自动投递、招聘消息发送、
凭证提取、登录/CAPTCHA 绕过，也不会发布用户简历或私人岗位数据。
